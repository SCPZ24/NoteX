跟随彩色消息从左向右看。读者编号决定队列，队列把消息交给该行标为「活跃」的消费者。

刚刚发生了什么

    演示设定为 P = 4，初始 A 负责 Q0 / Q2，B 负责 Q1 / Q3。增加 C 的交接步骤为演示设定的订阅协调。SAC 按队列管理活跃消费者，负载分配需要应用层安排。本页使用 reader_id % 4 示意固定路由，每页 8 人；当前项目实际粉丝页上限为 500，Chunk 上限为 100。游标使用关系记录身份。

    本页演示扩容到 3 个分发进程。在 P = 4 且每分片串行的条件下，同阶段最多 4 条活跃执行流；更多进程可以分担工作或提供备用，性能取决于进程预算及依赖瓶颈。交接进行时请先观察交接完成，再模拟故障；故障后可重置体验扩容。检测和交接时长均为动画设定。正常交接简化了网络往返，实际仍需要在途准入与幂等保护。

    本页展示 MQ 中未 ACK 消息的恢复。项目中已 ACK、落在 MySQL 的重试任务，还需要设计分片归属与执行调度。接管允许重复执行，最终数据正确性依赖幂等与条件写入。
